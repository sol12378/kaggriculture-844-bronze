# 教訓

## うまくいったこと

- **公開リプレイを材料にした蒸留**。提出前の探索を、リーダーボード上位の実際の対戦から作った候補に切り替えたことが、最終スコアにつながりました。
- **開発用と検証用のリプレイ分離**。同じ試合が両方に入らないようにしたため、検証データへの過学習を避けられました。
- **複数のシード群での再対戦**。最初の順位がシード群で反転することを確認し、1回の総当たりの結果を鵜呑みにしませんでした。
- **提出前のパッケージ検証**。展開した `main.py` を、Kaggle と同じパスローダーで両座席から動かしました。

## うまくいかなかったこと

- **ローカルの勝率はホストのレーティングを予測しませんでした。** `Top20 counter small5` はローカルで 58勝6敗でしたが、ホストでは約5割でした。
  `rank95_front97` はローカル 61.9%、提出直後の公開スコア 1057.9、最終 2185.6 でした。ローカルの相手集合は、ホストの相手分布を代表していませんでした。
- **提出アーカイブの入口関数の不具合**。`main.py` の最後の関数がエージェント関数でなかったため、ホストでは全手 PASS になりました。
  パスローダー経由の検証を、提出前の必須手順にするべきでした。
- **元ファイルの喪失**。`D3_MARKET_CAP_V1` を提出したのに、その元ファイルを保存していませんでした。提出物は、ハッシュ付きで必ず保存します。
- **提出直後のスコアの読み違い**。提出直後のスコアは数試合分の暫定値で、判断の根拠になりません。

## 次にやるなら
